# Zerar issues: #396–#405, #407, #408

## Objetivo
Fechar as doze issues abertas depois da 1.41.0 numa rodada só (MINOR 1.42.0 — três hooks novos e uma checagem nova no `/saude`): aviso de fluxo no primeiro Edit de código, catraca de plano no `cobertura`, baterias que medem o que dizem, `limpar` que revalida no instante, `conferir-entrega` que lê só o stdout, idioma reinjetado na compactação, gate de instalação para subagente, payload de bateria por `JSON.stringify`, skill divergente entre config dirs, dois falsos positivos do `gate-fechar-issue` e data local na memória.

## Decisões fechadas

### #405 e #407 — `gate-fechar-issue`
- **D1 — #405: `bash`/`sh` com caminho de script que contém variável (`bash scripts/$b.sh`, `bash "scripts/$b.sh"`) deixa de ser ilegível no `gate-fechar-issue`; vira script desconhecido (passa). `desempacotarWrapperDeString` em `hooks/lib/tokens-comando.cjs` ganha a opção `{ scriptComVariavel: 'desconhecido' }`, que o `gate-fechar-issue` passa e o `gate-subagente-sem-gh` não** — porquê: a regra que barra é `contemConstrucaoIlegivel(current.tok + coladoNoToken)` em `tokens-comando.cjs:871`, que trata qualquer `$` no caminho do script como ilegível; reproduzido nesta sessão: as três variantes saem exit 2 sem `gh` na linha. O script indicado por variável é o mesmo caso de um script literal que o gate não lê por inteiro — a ideia `gate-por-parser-de-shell-e-poco-sem-fundo` registra que perseguir isso não tem fundo. O `gate-subagente-sem-gh` mantém a recusa porque lá o custo de deixar passar é um subagente fechando Issue.
- **D2 — #405: `eval`/`bash -c`/`sh -c` com string que contém variável continuam ilegíveis** — porquê: aí o comando inteiro está na variável e pode ser o próprio `gh issue close`; o #405 é sobre caminho de script.
- **D3 — #407: quando o `--body-file` não é legível e o mesmo comando tem um heredoc redirecionado para exatamente esse caminho (`cat > x.md <<'EOF'` … `EOF`, também `>|` e `tee x.md <<`), o gate decide pelo corpo do heredoc, com as mesmas regras do arquivo existente; o corpo vem de `corpoDeHeredoc` (`hooks/lib/heredoc.cjs:138`)** — porquê: o gate lê o arquivo no PreToolUse, antes do comando rodar (`gate-fechar-issue.cjs:535`); o parser de heredoc já existe e o gate já o importa (`:39`).
- **D4 — #407: sem arquivo e sem heredoc que o crie, a mensagem de ilegível nomeia as duas saídas: "grave o corpo antes (ferramenta de escrita) e rode o `gh` em seguida"** — porquê: a mensagem atual (`:714`) não diz por que o arquivo não foi lido.

- **D7 — também nega criar o arquivo `.rainforest-gate-off` (Write/Edit com esse nome; Bash/PowerShell com `>`, `touch`, `New-Item`, `cp`/`mv`/`Copy-Item` para esse nome) e definir `RAINFOREST_GATE_OFF` (`export`, prefixo `RAINFOREST_GATE_OFF=`, `$env:RAINFOREST_GATE_OFF`, `setx`)** — porquê: são as duas chaves de desligar gate que existem (`gate-fechar-issue.cjs:1035-1039` e os outros nove gates); a observação é de um executor que criou o arquivo, commitou e removeu.
- **D8 — o hook novo não honra `RAINFOREST_GATE_OFF` nem `.rainforest-gate-off`; desliga só pela chave `subagente-sem-instalar` do config** — porquê: o gate existe justamente contra quem cria essas chaves; mesmo desenho do `gate-subagente-sem-gh` (`:190-193`).

Abra o fluxo (<comando>) ou diga ao usuário que pula, e por quê."; chave de config `aviso-fluxo` (boolean, padrão true)** — porquê: a regra é "pular calado não vale" (modo-dev); a mensagem dá as duas saídas.

### #401 — idioma na compactação
