# Design: decisão de API de framework cita a documentação oficial no `busca:` do plano

## Objetivo
O campo `busca:` do plano procura reuso (`repo`, `livro`, `ideias`), e nada nele fundamenta a
API de framework ou biblioteca que a tarefa vai usar. Hoje essa escolha sai da memória de treino
de quem escreve o plano, que pode estar numa versão antiga da biblioteca. O
`addyosmani/agent-skills` (MIT, `source-driven-development`, lido no código em 2026-11-07, linha
do livro de repos) faz cada decisão de API citar a doc oficial da versão em uso, com uma
hierarquia de fontes e uma marca para o que a doc não cobre. Este fluxo enxerta só o método,
como um canal `doc` no `busca:`. Modo autônomo ("oq mais tem para melhorar das ideias, pode ir
fazendo", 2026-11-08): as decisões marcadas **[sessão]** foram a recomendada, sem rodada, e
ficam para veto no PR.

**Fato medido antes do design:** `lerLinhaBusca` em `scripts/conferir-busca.cjs` já aceita
qualquer nome de canal. Uma linha `- doc | <url> | <resultado>` passa na base hoje, e uma linha
`- doc | sem url | x` também. Nenhum plano em `docs/rainforest/planos` usa o canal `doc`
(`grep -rnE "^\s*- doc \|" docs/rainforest/planos` sem saída), então validar a forma não recusa
plano antigo.

## Decisões fechadas
- **D1 — Canal `doc` com consulta que é URL [sessão]** — porquê: a doc citada tem que dar para ser aberta por quem revisa o plano. Sem URL, "li a doc" é afirmação de memória. Forma: `- doc | <URL http(s) da página oficial> | <o que a página diz que decide a API>`. O `conferir-busca.cjs` recusa a linha `doc` cuja consulta não é só a URL: `http://` ou `https://` seguido de algo sem espaço, e nada depois. `- doc | pulado: <motivo>` continua aceito, como nos outros canais que não são o `repo`.
- **D2 — A linha `doc` é conferida em toda tarefa que a declara [sessão]** — porquê: decisão de API costuma editar arquivo que já existe, e o checador hoje só lê o `busca:` de tarefa `implementar` que cria caminho novo. Assim a linha `doc` passaria sem ser lida. A conferência da forma da linha `doc` vale para qualquer tarefa com bloco `busca:`, de qualquer tipo, e não exige git. As outras regras do bloco (`repo` obrigatório, `desfecho:`) continuam só nas tarefas que criam caminho novo de código, como hoje.
- **D3 — Quando usar, hierarquia de fontes e a marca do que a doc não cobre, na referência do campo [sessão]** — porquê: o checador confere a forma, não o mérito. O método vai em `skills/plano/references/campo-busca.md`, e uma frase em `skills/plano/SKILL.md` aponta para lá. Quando: tarefa que escolhe ou usa API de framework ou biblioteca de terceiro. Página da versão em uso (lida no manifesto ou no lockfile). Hierarquia: doc oficial, depois changelog ou blog oficial, depois padrões web (MDN, RFC), depois tabela de compatibilidade. Stack Overflow, tutorial e memória de treino nunca são fonte. Quando a doc não cobre o ponto, o resultado começa com `não verificado:` e diz o que faltou. A marca é a mesma ideia do `UNVERIFIED` do agent-skills, em português, como o resto do repo.
- **D4 — Versão MINOR, com CHANGELOG e README** — porquê: canal novo conferido é contrato novo para quem escreve plano (tabela do `CONTRIBUTING.md`: campo e trava nova são MINOR). 2.8.2 → 2.9.0.

## Avaliado e descartado
- Detectar sozinho a tarefa que decide API (por exemplo, `arquivos:` tocando `package.json`): o sinal erra para os dois lados. Tarefa que usa uma API nova de biblioteca já instalada não toca manifesto, e bump de dependência toca manifesto sem decidir API. Exigir `doc` com esse gatilho daria recusa falsa e escape fácil.
- O checador abrir a URL para conferir que a página existe: rede dentro de um checador de plano quebra no CI e offline, e a página existir não prova que diz o que o resultado diz.
- O cache por ETag do `sdd-cache` do agent-skills: exige `jq`, `curl` e `shasum` e configuração manual no `settings.json`, e o `WebFetch` já basta para ler a página.
- Exigir a marca `não verificado:` pelo checador: ele não tem como saber se a doc cobre o ponto.

## Fora de escopo
- Citar a doc no design do `brainstorm`: o plano é onde a API vira tarefa, e é o que o `executar` lê.
- Conferir os outros canais (`livro`, `ideias`, `memoria`, `web`) em tarefa que não cria caminho novo: mudaria o que o checador recusa hoje sem um caso que peça isso.
